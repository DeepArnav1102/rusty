# CLI Remote Features Implementation Plan

This document outlines the specific changes needed *only* in the `rusty` CLI codebase to support remote branches, pulls, and checkouts. It also highlights critical edge cases to handle.

## 1. Remote API Client (`src/remote.rs`)
**Goal:** Enable the CLI to fetch the full state of remote branches, rather than just querying the currently active branch.
*   **Change:** Add a `get_all_refs(origin: &str, creds: &Credentials)` function.
*   **Action:** This will call the backend's new `GET /refs` endpoint and return a map or list of `branch_name -> commit_hash`.
*   **Edge Cases:**
    *   **Network Failure:** Handle timeouts or 500 errors gracefully, informing the user "Could not reach remote."
    *   **Empty Repo:** Handle the case where the remote repository has no branches/commits yet (e.g., return an empty map instead of panicking).

## 2. Fetching All Branches (`src/fetch.rs`)
**Goal:** Download objects for *all* remote branches and update local remote-tracking references.
*   **Change:** Modify `fetch(repo_path: &Path)` to call `get_all_refs`. Iterate over every returned branch.
*   **Action:** For each branch, fetch the missing commits/trees/blobs. Finally, write the commit hash to `.git/refs/remotes/origin/<branch_name>`.
*   **Edge Cases:**
    *   **Stale Remote Refs:** If a branch was deleted on the remote, it will no longer be returned by `get_all_refs`. We should prune (delete) the local tracking branch in `refs/remotes/origin/<branch_name>`.
    *   **Partial Fetch Failure:** If fetching one object fails (e.g., network drop), abort cleanly so the repository state doesn't get corrupted with half-downloaded trees.

## 3. Remote-Aware Branching (`src/cli.rs` & `src/branch.rs`)
**Goal:** Allow users to see remote-tracking branches.
*   **Change in `cli.rs`:** Add `#[arg(short, long)] remote: bool` and `#[arg(short, long)] all: bool` to `Commands::Branch`.
*   **Change in `branch.rs`:** Update `list_branches` to check these flags.
*   **Action:**
    *   If `-r`, list files in `refs/remotes/origin/`.
    *   If `-a`, list files in `refs/heads/` and `refs/remotes/origin/`.
*   **Edge Cases:**
    *   **Missing Directories:** The `refs/remotes/origin/` directory might not exist yet if the user has never run a fetch. Ensure `fs::read_dir` doesn't panic; it should gracefully return zero branches.

## 4. Checking Out Remote Branches (`src/checkout.rs`)
**Goal:** Automatically create a local branch when checking out a remote branch that doesn't exist locally.
*   **Change:** In `checkout(repo_path, branch)`, add fallback logic.
*   **Action:** 
    1. Check if `refs/heads/<branch>` exists. If yes, proceed with normal checkout.
    2. If no, check if `refs/remotes/origin/<branch>` exists.
    3. If yes, copy the hash from the remote ref to create `refs/heads/<branch>`, then proceed with the checkout.
*   **Edge Cases:**
    *   **Detached HEAD:** Make sure that when we create the local branch, `HEAD` is correctly updated to `ref: refs/heads/<branch>` rather than just writing the raw commit hash to `HEAD` (which causes a detached state).
    *   **Uncommitted Changes:** If the user has uncommitted changes that conflict with the remote branch's files, `checkout` should abort with an error to prevent overwriting their work.

## 5. Robust Pull & Push (`src/pull.rs` & `src/push.rs`)
**Goal:** Prevent crashes on newly created local branches and handle out-of-sync pushes.
*   **Change in `pull.rs`:** Add validation before merging.
*   **Action:** After fetching, before calling `merge("origin/<branch>")`, verify that `refs/remotes/origin/<branch>` actually exists. 
*   **Edge Cases (Pull):**
    *   **No Upstream Branch:** The user created a branch locally and ran `pull`. Catch the missing remote ref and tell them: "No remote tracking branch to pull from."
    *   **Merge Conflicts:** Ensure `pull` correctly bubbles up the conflict message generated by `merge.rs`.
*   **Change in `push.rs`:** Ensure pushing handles server rejections cleanly.
*   **Edge Cases (Push):**
    *   **Remote Ahead (Rejected Push):** If the remote branch has new commits that the local branch doesn't have, the backend will reject the push. `push.rs` must catch this 400/409 HTTP error and explicitly tell the user: "Updates were rejected because the remote contains work that you do not have locally. Run 'rusty pull' first."
